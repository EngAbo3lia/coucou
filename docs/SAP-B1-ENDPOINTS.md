# SAP Business One Service Layer — endpoint map

How Coucou talks to Business One, what every endpoint can do, and how to query
or create against each family. Generated from a live sweep of
`TESTING01.ETA` (Business One version `1000340`).

The schema itself is not in this file. It is generated into
`windows/src-tauri/src/sapb1/catalogue.rs` (460 entity sets, 427 types, every
field with its type), stamped with the version it was built from. Refresh it —
only when the version changes — with `windows/scripts/refresh-sap-schema.ps1`.
This file is the shape that catalogue does not carry: capability and recipes.

## Transport

| Piece | Value |
|---|---|
| Base path | `https://<host>:50000/b1s/v1` (OData v3) and `/b1s/v2` (OData v4) |
| Login | `POST /Login {CompanyDB, UserName, Password}` → `SessionId`, `Version` |
| Session | `Cookie: B1SESSION=<id>`; 30 minute timeout; re-login on expiry |
| Metadata | `GET /$metadata`, ~2.1 MB — the authority for every field |
| Version | Always in the login response. The schema is stale only when it differs. |

`Version` is the tag the catalogue carries as `SAP_VERSION`. The SAP Harness
compares it at connect time and says **Schema out of date** when it differs.

## Read surface

457 entity sets are exposed. 452 answer a plain `GET ?$top=1&$count=true`.
5 fail:

| Endpoint | Result |
|---|---|
| `InternalReconciliations`, `ElectronicDocuments`, `ExportDeterminations`, `ImportDeterminations` | HTTP 502 |
| `SBOMailers` | not an entity set |

Every set is reachable through the catalogue. The largest by rows on this
company: `FormPreferences` 29,320 · `ExchangeRates` 13,188 · `JournalEntries`
6,813 · `Invoices` 1,413 · `DeliveryNotes` 1,368 · `Orders` 1,264.

## Write surface

A `POST` with an empty body to every set, grouped by the SAP error code it
returned. The HTTP status alone is misleading: business errors come back as 404
too (`-2028: Customer record not found`), so the code decides.

| Code | Sets | Meaning |
|---|---|---|
| `-5002` | 237 | Needs a field. The message names it: `[OITM.ItemCode]`, `[OOSR.Descript]`. |
| `-1` | 68 | SQL Server rejected the insert (a NOT NULL column was empty). Creatable. |
| `-1008` | 61 | `Command Not Found` — **not creatable** through this path (views, reports, actions). |
| `-2028` | 33 | A referenced record is missing (`Customer record not found`). Creatable with valid keys. |
| `-10` | 23 | Invalid value. Creatable. |
| 201 | 19 | Accepted an empty body but the path is not queryable — action/function endpoints, not entities. |

So roughly **380 sets are creatable**, and the ones that matter want specific
fields. 145 of them name the field directly; the map is regenerated by
`windows/scripts/gen-sap-endpoint-map.ps1`.

## Query recipes

Verified against this server (`src-tauri/src/sapb1/query.rs` holds the matrix):

| Want | Use |
|---|---|
| Rows | `Set?$top=N&$skip=M` (`$skip` before `$top`) |
| Sort | `Set?$orderby=DocDate desc` — raw fields only, not aggregate aliases |
| Exact count | `Set/$count?$filter=...` |
| Date filter | `$filter=DocDate ge datetime'2015-01-01'` (bare date also works) |
| Totals | `$apply=aggregate(DocTotal with sum as Total,$count as Cnt)` |
| Group | `$apply=groupby((CardCode),aggregate(DocTotal with sum as Total))` |
| **Not** filter+apply | `$apply` with `$filter` → `HTTP 400 Not supported query option`. Filter in Rust. |
| **Not** expand lines | `$expand=DocumentLines` → 400. Lines come only on `Set(key)`. |

## The families you asked for

### Customers and items

`BusinessPartners` (36 rows, 328 fields), `Items` (101 rows, 310 fields).
Both creatable. `Items` needs `ItemCode`; `BusinessPartners` needs `CardCode`.
Documents additionally need the partner's `BillToState` — Business One derives
the US tax extension from it, and an unset state rejects every document for that
partner. `create_document` refuses by name before the write.

### Inventory and stock transfers

| Endpoint | Rows | Fields | Kind |
|---|---|---|---|
| `StockTransfers` | 25 | 93 | Document. Create with `DocDate` + `StockTransferLines` (or `StockTransferLinesWithBatch`). |
| `InventoryGenEntries` | 148 | 289 | Goods receipt. Needs `DocDate` + `DocumentLines`. |
| `InventoryGenExits` | 2 | 289 | Goods issue. Same shape. |
| `InventoryTransferRequests` | 0 | 0 | Request draft, then generate the transfer. |
| `Warehouses` / `WarehouseLocations` | 8 / 8 | 97 / 32 | Master data. |

Inventory postings are real stock movements and cannot be cleanly deleted.

### Employees

`EmployeesInfo` (9 rows, 126 fields), `SalesPersons` (7, 12). `EmployeeIDType`,
`EmployeeRolesSetup` are setup. Read-heavy; creation needs the full employee
record.

## Write rules that always hold

1. **Ask the server first.** `BillToState`, required fields, series, and
   exchange rates are company data. A field that is optional elsewhere is
   mandatory here.
2. **Dates carry the exchange rate.** `A00001` is USD; this company has no rate
   for the current date, so a foreign-currency posting fails with
   `HTTP 400: Update the exchange rate , 'USD'` unless the date has one.
3. **A copy is a base document, not rebuilt lines.** Post `BaseEntry` /
   `BaseLine` / `BaseType` (`17` sales order, `540` purchase order); the server
   reads price, tax and currency from the source.
4. **Never hand-write `TaxExtension`.** It is derived from the partner.
5. **Register before you post.** Every create goes through the document
   registry and the confirm dialog. Nothing writes silently.

## Recovery: a failed write says what it needs

`src-tauri/src/sapb1/recovery.rs` reads a rejected write and names the fix, so
the agent can act instead of showing `-10 Quantity falls into negative
inventory`.

| Server says | Fix | Offered next step |
|---|---|---|
| `negative inventory` | `ReceiveStock` | `receive 1000 <item>` |
| `batch/serial numbers` | `BatchSerial` | supply the numbers |
| `exchange rate , 'USD'` | `ExchangeRate` | pick a dated rate or another date |
| `TaxExtension.BillToState` / `billing state` | `PartnerState` | `set the billing state on <card>` |
| `Enter due date` | `DueDate` | give a due date |
| `item number is missing` / `item not found` | `CreateItem` | `create item <code>` |
| `Customer record not found` | `CreatePartner` | `create customer <card>` |
| `[TBL.FIELD]` | `MissingField` | the field it named |
| anything else | `Unknown` | the server's own words, verbatim |

`create_document` wraps `transport::post` with `recovery::explain`, so every
write failure is already actionable. The `suggestion` string is the question the
chat can offer as a follow-up.

## Entity writes: the form asks for exactly what the entity needs

`src-tauri/src/sapb1/entities.rs` describes the writable entities beyond sales
and purchase documents, once:

| Entity | Fields asked | Lines |
|---|---|---|
| `Items` | `ItemCode` *, `ItemName` *, `ItemsGroupCode` (100) | no |
| `BusinessPartners` | `CardCode` *, `CardName` *, `CardType` * (`cCustomer`/`cSupplier`/`cLead`), `Country` *, `Currency` *, `BillToState` * | no |
| `InventoryGenEntries` | `DocDate` *, `WarehouseCode` * (01) | yes |

The planner gains three kinds — `receive` (goods receipt), `new_item`,
`new_partner` — which return a **confirm form**: `payload` carries
`{ set, fields:[{key,label,kind,required,value,options}], lines }`. The chat
renders one input per field (a `select` for a choice), prefilled from the
planner's guess, and posts only after the user confirms. `kind` is `text`,
`number`, `date` or `choice`.

`mod::write_entity` re-checks the required fields server-side (`Fill in … before
posting`), builds the body, and maps any refusal through the same `recovery`
rules. `sap_b1_write_entity` is the Tauri command; `Bridge.sapB1WriteEntity` in
`core/bridge.ts` calls it.

Verified live: `write_entity` created item `DEMO-W01` and goods receipt
`DocEntry 170`.

## Discovery log

Everything below was learned by hitting the live `TESTING01.ETA` server
(B1 `1000340`) — read-only where possible, writes only on the disposable
learning company.

### Tooling

- `Invoke-RestMethod` against this Service Layer fails with a spurious
  `400 Invalid login credential` and does not accept `-SkipCertificateCheck`
  in Windows PowerShell 5.1. `curl.exe -sk` is the transport that works.
- An inline JSON body passed to `curl` from PowerShell is mangled and the server
  answers `-1 BadFormat`. Write the body to a file and use `--data-binary "@file"`.
- PowerShell interpolation eats `$var:` and `$var?`. Use `${var}` — this bit the
  sweep, where `"$set?..."` silently deleted the whole path.
- Windows Credential Manager stores these as generic credentials under
  `LegacyGeneric:target=<key>.fr.louisraille.coucou`, secret as UTF-16 in
  `CredentialBlob`. `CredRead` reads them; `CredEnumerate` in PS 5.1 does not.
- The login response carries `Version` (`1000340`), `SessionId`,
  `SessionTimeout` (30 min). That version is `catalogue::SAP_VERSION`.

### Read

- 457 entity sets exposed; 452 readable with `?$top=1&$count=true`.
- 5 fail: `InternalReconciliations`, `ElectronicDocuments`,
  `ExportDeterminations`, `ImportDeterminations` → 502; `SBOMailers` → not an
  entity set.
- `Invoices` `GET` with no `$select` returns 327 fields and the nested
  `DocumentLines`; `$expand=DocumentLines` is still rejected.

### Write

- Status alone cannot classify: SAP returns HTTP 404 for business errors
  (`-2028: Customer record not found`). The JSON `error.code` decides.
  Counts: `-5002` 237, `-1` 68, `-1008` 61, `-2028` 33, `-10` 23, 201 blank 19.
- `-1008 Command Not Found` is the read-only / action set (views, reports,
  `FormPreferences`, `FinancialReportTemplates`).
- POSTing `{}` to 19 non-entity action paths answers 201 but the path is then
  `Unrecognized resource path` on GET — nothing queryable is created.

### Verified create bodies

| Entity | Minimum that works |
|---|---|
| `Items` | `ItemCode`, `ItemName`, `ItemsGroupCode`, `InventoryItem/SalesItem/PurchaseItem = tYES` |
| `InventoryGenEntries` | `DocDate` + `DocumentLines[{ItemCode, Quantity, WarehouseCode, UnitPrice}]` |
| `BusinessPartners` | `CardCode`, `CardName`, `CardType=cCustomer`, `Country`, `Currency`, `BillToState` |
| `Invoices` | `CardCode`, `DocDate`, `DocDueDate`, `DocumentLines[{ItemCode, Quantity, UnitPrice}]` |

### Traps, each seen live

- **Negative inventory.** An invoice for an item with no stock fails:
  `-10 Quantity falls into negative inventory [DocumentLines.ItemCode]`. Items
  need a goods receipt first. Order: item → `InventoryGenEntries` → invoice.
- **Batch/serial items.** An invoice line for an item with serial/batch
  management fails `-4014 Cannot add row without complete selection of
  batch/serial numbers`, even with `SerialNumbers` absent. Use items without
  management, or supply the numbers.
- **State belongs to a country.** A partner state is validated against `States`:
  `-2028 [OCRD.State1] 'Linked value 1 does not exist'` — `1` is Saudi Mekka.
  `[OCRD.State2] 'Linked value CA does not exist'` for `ShipToState` when
  `Country` is not `US`. Set `Country=US` and `BillToState=CA` (the working
  partner `C70000`), and do not set `ShipToState` on a partner with no address.
- **Exchange rate.** A USD posting on a date with no rate fails
  `HTTP 400: Update the exchange rate , 'USD'`. GBP postings are unaffected.
- **Orders need a due date.** `HTTP 400: Enter due date [ORDR.DocDueDate]`.
- **Tax extension is derived.** Never send `TaxExtension`; an unset partner
  `BillToState` is rejected by the server as `TaxExtension.BillToState`.

### Seeded demo dataset (learning company)

`windows/scripts/seed-demo-data.ps1 -Invoices 100` created, in dependency order:
5 items `DEMO-I01..I05`, a goods receipt per item (stock), 3 customers
`DEMO-C01..C03` (US/CA, GBP), and 100 A/R invoices across 2026 Q3.

Ground truth for the chat, as of this seed: **Q3 2026 (2026-07-01 .. 2026-09-30)
= 107 invoices, 92,053.20 GBP** net (the 100 seeded plus 7 from earlier runs).
A correct answer to "sales last quarter" must match that.

### Two bugs that made that total read zero

Found by testing the seed against the real chat, both fixed:

1. **The page is capped at 20 rows.** `Invoices?$top=5000` returns 20 rows and an
   `odata.nextLink`; the rest are only reachable with `$skip`. A single read
   therefore saw the oldest 2015 invoices and summed the quarter to `0`.
   `fetch_rows` now pages (`query::build_page_url`) until the rows run out or
   `ROW_CAP` is reached.
2. **The window's end day was formatted in the wrong month.** `LastQuarter` took
   the day of `2026-09-30` and printed it as `2026-10-30`, and `LastMonth`/
   `ThisQuarter` had the same fault. The day and its month now come from the same
   computed date. Separately, a `DocDate` of `2026-09-30T00:00:00Z` compared
   against the bound `2026-09-30` sorted *after* it (the `T`), dropping the last
   day; both sides are trimmed to `YYYY-MM-DD` before comparing.

After both fixes, `live_last_quarter_total_is_not_zero` reports
`total=92053.20, source=Invoices, 2026-07-01..2026-09-30`.
